# Slice 3 Implementation Plan: task markers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `kanjo mark start|end|current`, an append-only marker journal in SQLite, and per-message attribution of Claude usage (marker > map > heuristic > `-`), reported by `usage` and the page.

**Architecture:** `internal/core` gets the marker types, a pure `Timeline.TaskAt`, the start/end rules and a `Journal` port. `kanjotest` gets a `MemJournal` and a `JournalContract`. `sqlitestore` implements the port and migrates the schema to version 2. `claudecode.Source` receives a `core.Timeline` and attributes each message. `cli` wires `mark` and `snapshot`. `core.Aggregate` computes the attribution counts that `usage` and `/api/data` show.

**Spec:** `docs/superpowers/specs/2026-11-03-markers-design.md` (decisions, edge cases, threat table). Founding: `docs/spec.md` sections 6, 8, 15.

## Review Focus

- A slot holding several tasks: replace, keep and cross-task cases of the merge rule.
- Boundaries: message exactly at a `start`, exactly at an `end`, in the same millisecond as a marker.
- Version 1 databases: read-only open (`usage`, `--all`, `serve`) must keep working before any migration.
- Two `mark` processes at once; clock behind; the cap.
- Page and CLI attribution numbers equal.

### Task 3: Start, end and current rules with the Journal port

**Files:** Create `internal/core/journal.go`, `internal/core/journal_test.go`; modify `internal/core/ports.go` (or keep the port in `journal.go`).

**Interfaces — Produces:**
```go
type Journal interface {
    // Update runs fn on the events of one scope inside an exclusive
    // transaction; a non-nil Marker returned by fn is appended with the
    // next id. fn returning an error aborts with nothing written.
    Update(ctx context.Context, session string, fn func(events []Marker) (*Marker, error)) error
    Markers(ctx context.Context) ([]Marker, error)
}
var ErrClockBehind, ErrNothingToEnd, ErrJournalFull error
func StartTask(ctx context.Context, j Journal, clk Clock, session, task string, maxEvents int) (Marker, started bool, err error)
func EndTask(ctx context.Context, j Journal, clk Clock, session string, maxEvents int) (Marker, error)
func CurrentTask(tl Timeline, session string, at time.Time) (task string, ok bool)
```
The cap counts all events of the journal, so `Update`'s `fn` also needs the total: pass it as a second argument (`fn func(scope []Marker, total int)`).

### Task 7: `marked` on usage rows and the slot-set merge rule

**Files:** Modify `internal/core/model.go` (`UsageRow.Marked`, validation `0 <= Marked <= Messages`), `internal/core/ports.go` (Merge doc), `internal/sqlitestore/store.go` (Merge, Rows), `internal/kanjotest/fakes.go` (`MemStore.mergeRow`), `internal/kanjotest/contracts.go` (store cases); tests in `internal/core/model_test.go`.

**Merge rule (design, "Recompute and idempotence"):** per slot `(source, session, day, model, long_context)`, compare the stored total messages with the incoming total; keep stored if larger, else replace the whole set. Do the comparison inside the transaction in Go (read totals, then delete and insert); the old per-row `NOT EXISTS` guard cannot insert several rows of one slot.

- [ ] **Step 1: Red tests:** `TestUsageRowValidateMarked` (negative, above messages); store contract cases, run on both stores: "two tasks in one slot are both kept", "a slot is replaced as a set when the incoming total is equal or larger" (marker added later: one `ABC-1` row of 5 becomes `ABC-1` 3 marked + `ABC-2` 2 marked), "a smaller incoming slot never shrinks saved usage, whatever its tasks", "marked is stored and returned", "other slots of a session are untouched".
